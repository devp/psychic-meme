# reality-check

Not a planning session — user is already overwhelmed or foggy. Goal is one small doable
next action, fast.

## Procedure

1. Ask briefly, 1-2 questions at a time, not a form: what's actually due today, what's
   making them stuck right now, what's already half-started.
2. Pull Todoist/Calendar MCP data only if it'll ground the answer and isn't already
   obviously known — don't turn this into a research detour.
3. Cut the list down out loud: name what can wait, what's someone else's turn, what's
   fake-urgent.
4. Land on ONE next action — small enough to start in under 10 minutes, concrete enough
   there's no "figure out how" step left.
5. Stop there. Don't hand back a full day plan — that's `/grwm`'s job, not this one.

## Tone

Coach, not checklist. Short questions, reflect back what's actually stuck vs what's noise.
This is one of the few times human-register prose fits even outside discussion mode — user
is stuck, not scanning a doc.

## Guardrails

- Read-only against any MCP.
- Resist solving the underlying task yourself — the job is finding the next action, not
  doing it.
